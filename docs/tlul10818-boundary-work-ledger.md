## Status vocabulary

- `PROVEN`: current source and verification evidence establish the item.
- `STATIC_READY`: the admission path exists, but target runtime evidence is
  still missing.
- `PENDING_EXTERNAL`: completion requires evidence generated by the external
  runner or CI.
- `NOT_STARTED`: necessary implementation does not yet exist.
- `REJECTED_CURRENT_CONTRACT`: useful idea, but deleting it does not prevent the
  current benchmark Contract from being proven.

## Completion Contract

The benchmark is complete only when a pinned finite parameter grid has been
fully enumerated on the known bad and fixed revisions, the resulting raw
evidence passes the sidecar adjudicator, and the report shows—without mixing
selector behavior with execution backend behavior—how many state evaluations
and how much wall time each selector needed to reconstruct the known boundary
at each reported accuracy.

Unknown-bug discovery, PPO/RL superiority, and GPU superiority of the selector
algorithm are not completion criteria.

## Sweep-axis ideas and feasibility

The values of an ordered axis must come from the requester, target
specification, or an externally owned experiment plan. This ledger does not
invent grid limits.

| Candidate axis | Kind | Current support | Admission issue |
| --- | --- | --- | --- |
| `request_integrity` | categorical | Existing `valid` / `malformed` input | Already suitable as a compatibility axis. |
| `d_response_observation` | categorical | Existing immediate / boolean-backpressured behavior | Useful, but does not measure a stall-length boundary. |
| `malformed_injection_cycle` | ordered | No independent wrapper control | Needs a schedule-defined injection cycle and a stable checkpoint interpretation. |
| `backpressure_cycles` | ordered | Runner schedule can hold `d_ready` low for a nonnegative number of `WaitD` cycles | Exact finite values must be declared by the external experiment Contract. |
| `response_delay_cycles` | ordered | Runner schedule can delay `response_valid_i` for a nonnegative number of `WaitD` cycles | Exact finite values must be declared by the external experiment Contract. |
| `outstanding_depth` | ordered structural parameter | Current DUT instantiation fixes `Outstanding(1)` | May require separate builds and manifests; comparability must be defined before admission. |

The first three timing candidates are the smallest plausible source of a real
boundary. `outstanding_depth` remains a candidate until the Contract explains
how separate compiled models share checkpoint, executor, and budget authority.

## Ideas rejected from the current Contract

- PPO or another RL policy before a history-dependent necessity is observed.
- Unknown-bug discovery before the known #10818 ground truth benchmark passes.
- A second benchmark IP before #10818 produces its first admitted report.
- A GPU-selector superiority claim; GPU launch throughput and selector sampling
  efficiency remain separate measurements.
- Treating the existing 4096 copies of one action as a 4096-point parameter
  ground truth.
